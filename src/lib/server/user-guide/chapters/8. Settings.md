# 8. Settings

Open **Settings** with the gear icon at the far right of the top toolbar.
- **Left side:** a **Search settings** box, then the six sections. Type in the box to show only the sections that match; the matching setting is shown under the section's name.
- **Right side:** the section you picked. Its header shows the section's icon, name and a one-line description, and its settings are listed below.

| Section | What you can change |
|---|---|
| **Agent** | Your profile, the model and prompt, how answers are generated, how documents are retrieved, and the assistant's persona |
| **Tools** | How many rounds of tool calls the assistant can make, and which tools it may use |
| **Models** | Downloading local models, the device they run on, and online or self-hosted providers |
| **Embeddings** | The model that prepares your documents for Semantic search |
| **Appearance** | Light or dark mode and the color theme |
| **Diagnostics** | Health checks and a log of recent activity, for when something goes wrong |

> **Good to know:** changes are saved as you make them; there is no Save button. **Agent** and **Tools** choices are saved to the current **profile**.

## What's in Agent

**Profile**

A profile saves your model, prompt, generation and retrieval choices together. Create one per task, for example "Quick answers" and "Deep research", and switch between them. Left to right:
1. **Profile** (dropdown): switches to another profile.
2. **Delete profile** (trash): deletes the current profile. It asks first.
3. **New profile** (+): asks for a **Profile name** and creates a profile from the settings currently shown.

**Model & prompt**
1. **Provider and model** (dropdown): the model that answers, grouped by where it comes from (**Local models**, **Ollama** or a provider you've added). **Providers** at the top right jumps to the **Models** section.
2. **Prompt template**: the instructions the model starts every chat from. Left to right:
   - **Prompt template** (dropdown): **RAG Chat (default)** or a template you've made.
   - **Edit prompt template** (pencil) and **Delete prompt template** (trash): only available for your own templates, not the default.
   - **New prompt template** (page with a +): asks for a **Name**, a **Description** and the **System prompt**.

**Generation**
1. **Max output tokens** (default 4096): the longest answer the model may write. A token is roughly three-quarters of a word.
2. **Temperature** (0 to 2, default 0.2): how adventurous the wording is. Low values give focused, repeatable answers; high values give more varied ones.
3. **Sampling top K** (default 8): how many candidate words the model chooses between at each step. Lower is more predictable.

**Retrieval**
1. **Semantic / Lexical / Hybrid** (default **Hybrid**): the method the chat uses to find passages in your documents.
2. **Retrieved chunks** (default 5): how many passages are given to the model with each question. More chunks give the model more to work with but can add noise and slow down small local models. Start with 5; try 8–10 for broad questions.

See **5. Search and Retrieval** for how the methods differ.

**Persona**
1. **Persona** box ("Optional style, role, or response guidance"): extra instructions added to every chat, such as "Answer as a field medic, in short bullet points." Leave it empty for no persona.

## What's in Tools

Tools let the assistant do things during an answer instead of just writing text, such as searching your documents several times or running a calculation. From top to bottom:
1. **Agent turns** (slider): how many rounds of tool calls the model can make before it must answer. It goes from 1 to **Unlimited** (all the way right); the default is 6.
2. **Warning** (only if your model can't use tools): "The selected model doesn't support tool calls…". Pick a different model to use tools.
3. **The tools**: each has a checkbox, its name and a short description. Tick a tool to allow it, untick it to block it.

| Tool | What it does | Example Prompts |
|---|---|---|
| **Corpus details** | Lists the documents in your library | "Which documents do I have about safety?" |
| **Date & time** | Checks today's date instead of guessing | "How many days until the deadline?" |
| **Goal tracking** (off by default) | Keeps a checklist for long, multi-step requests | "Summarize each chapter, then write a conclusion." |
| **Python** | Runs calculations and draws charts using Python libraries; can read your CSV and text files | "Generate me a graph with my loaded csv file" |
| **Read document chunks** | Reads the text around a passage it found | "Read the section before that quote." |
| **Document search** | Searches your documents as many times as it needs | "Tell me how to treat severe bleeding" |

> **Good to know:** allowed tools only run when the **Tools** button in the chat box is on, in **Notebook** or **Search** mode (see **4. Assistant Chat**).

## What's in Models

**Local models**

Models that run inside the app, fully offline. One card for each built-in model. Each card shows, top to bottom:
1. The model's name, with an **Active** badge if it's the one in use.
2. Who made it and a link to its license.
3. A short description and how much memory it needs ("Needs ~8 GiB RAM").
4. Buttons: **Download** if it isn't downloaded yet, a progress bar while it downloads, or **Use this model** and **Delete** once it's on your computer. Only one download can run at a time. **Delete** asks first, and you can download the model again later.

| Model | Memory needed |
|---|---|
| **Gemma 4 E2B** | about 8 GB |
| **Gemma 4 E4B** | about 16 GB |
| **Gemma 4 26B A4B** | about 32 GB; for high-end computers with a dedicated graphics card |

**Local runtime** (only shown while a local model is in use)
1. **Compute device**: **Auto (recommended)**, **CPU only**, or your graphics card (**CUDA (NVIDIA)** or **Vulkan**) if you have one.
2. **Vulkan GPU** (only if the app finds a Vulkan graphics card): **Automatic** or a specific card. After changing it, restart the app to switch.

The context window (how much text the model can take in at once) is fitted automatically to your computer's memory.

**Providers**

Online or self-hosted services that offer models through an OpenAI-compatible connection.
1. One row for each provider you've added, left to right: its name (with an **Active** badge if its model is in use), web address, and "OpenAI-compatible · API key saved · N models". Then **Edit** (pencil) and **Remove** (trash). **Remove** asks first and also deletes the saved API key. With no providers, this reads "No providers added yet."
2. **Add provider** (+): choose **OpenAI-compatible**, then enter a **Name**, the **Base URL** (including `/v1`) and an **API key** if the service needs one. Its models then appear in the model picker.

## Ollama models (optional)
> **Only relevant if you already use Ollama.** If you don't know what Ollama is, skip this section: the **Local models** above do the same job without installing anything else.

Ollama is a separate, free program that runs AI models on your computer. Deployable Knowledge can use the models it has installed, but **Ollama must be installed and running on the same computer** for them to appear.

1. Install Ollama from [ollama.com/download](https://ollama.com/download) and start it.
2. Download a model in a terminal, for example `ollama pull gemma4:e4b`.
3. Open the model picker in **Assistant Chat**. The model appears in the **Ollama** group. If there is no Ollama group, Ollama isn't running or has no models yet.

Good to know:
- Ollama models run on your computer and work offline once downloaded. Models with `cloud` in their name are the exception: they run on Ollama's servers and need an internet connection.
- New models are always downloaded through Ollama itself; the app can't download them for you.
- Close Ollama and its models disappear from the picker until you start it again.
- If a model can't use tools, the **Tools** button in the chat box is greyed out.

## What's in Embeddings

The embedding model turns each chunk of your documents into a numeric fingerprint of its meaning, which **Semantic** search uses to find passages. It is separate from the model that writes answers.

**Local embedding models**

One card for each built-in embedding model, laid out like the cards in **Models**: name and **Active** badge, maker and license, description, then **Download**, **Use this model** or **Delete**. The active embedding model can't be deleted.

**Embedding model**
1. **Model** (dropdown): the embedding model in use. Switching asks first: all your documents are re-embedded in the background, and until that finishes Semantic search only finds the ones already done.
2. **Vulkan GPU** (only if the app finds a Vulkan graphics card): the same setting as in **Models → Local runtime**.
3. **Compute device**: **Auto**, **CPU** or **GPU**.
4. **Status line**: where the model is running ("Running on CUDA.", "Loads on first use."), and how many chunks are still waiting to be re-embedded. **Refresh embedding status** (circular arrows) updates it.

## What's in Appearance

Changes apply immediately.
1. **Color mode**: **Light**, **Dark**, or **System** (follows your computer's setting).
2. **Color theme**: **Classic**, **Purple**, **Blue**, **Yellow**, **Green** or **High contrast**. Each works in both light and dark mode.

## What's in Diagnostics

Diagnostics shows whether the app's parts are working and what it has been doing. Nothing here changes your settings. From top to bottom:
1. **Health badges**: **Database**, **Index** and **Embedding**, each with its state (for example "healthy" or "ready"). A red badge means that part has a problem. The app's version is on the right.
2. **Counts**: **Documents**, **Active**, **Chunks**, **Sessions**, **Messages**, **Notebooks**, **Pages**, and how much **Memory** the app is using.
3. **Toolbar**, left to right:
   - **all / info / warning / error**: show every event, or only events of that level.
   - **Refresh diagnostics** (circular arrows): checks the health and counts again.
   - **Pause event updates** (pause icon): freezes the log so you can read it; click again (play icon) to resume.
   - **Download .txt**: saves a report of the health checks and recent events.
4. **Event log**: one line per event, with its time, level, the part of the app it came from, and a message. It reads "No diagnostic events recorded." when there's nothing yet.

> **Good to know:** if you need help with a problem, attach the **Download .txt** report. It includes document names, but never their contents, your prompts, messages, searches or API keys.
